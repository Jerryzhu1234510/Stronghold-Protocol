# 不中断对局更新：第一阶段本地验收

这份代码只用于本地验收，还不能上传替换正在运行的腾讯服务器。

更新方式是保留旧进程、旧目录、旧连接，单独启动新进程。新进程健康检查通过后，首页才转向新版。旧版不再允许创建、加入或开始新对局，但当前对局操作、聊天、断线重连和结算继续可用。每个页面的模块、数据、图片和连接都绑定自己的版本，刷新正在玩的页面也仍回到原版本。结算后返回大厅，页面自动重新进入新版首页。

本地模拟测试覆盖了旧连接保持、断线恢复身份和房间、完成结算、新玩家进入新版、拒绝旧版再次开局、更新失败保留当前版本，以及真实 Match 在更新后继续接受操作。未做 200 人以上线上负载验收。

这套机制不保证服务器断电、进程崩溃或重启 Docker 后恢复对局。它目前没有完整对局持久化。首次安装需要一次计划停服；安装后更新游戏版本不需要重启入口进程。以后若要重启入口、更新 Node/Docker 或更改入口协议，也仍需要维护安排。

## 开发者本地操作

启动：`node server/hot/gateway.mjs`，默认监听本机 3222 端口。

在同一个运行窗口输入：

```
update C:\完整路径\新版独立目录
versions
retire 旧版本标识
announce 本次公告文字
```

每个新版必须放在独立目录，不能覆盖正在运行的版本。新版需要包含这套不中断更新协议；原来的 0.1.4 包不能直接作为更新目标。`retire` 只有在旧版本没有对局且没有连接时才成功，保留旧版本时不会删除文件。最多保留三个运行版本，防止反复更新积累进程；旧对局仍在运行时不能强制清理。

新旧版本并存会增加内存占用，需要在服务器验收时记录峰值。所有版本的在线人数统一汇总，并缓存一秒，避免每个玩家轮询都重复查询全部进程。统计页的详细流量和延迟记录仍按所查看版本显示。

## 后续服务器部署需要完成的工作
