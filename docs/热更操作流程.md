# 热更怎么操作

这份流程对应本次定制包。现在只做了本地验收，尚未操作腾讯服务器。先验收游戏，再安排首次安装。

## 对正在玩的玩家有什么影响

| 操作 | 正在进行的对局 | 后面进入的玩家 |
|---|---|---|
| 按下文 `update` 切换游戏版本 | 继续使用旧程序、旧地图和旧数值，直到这局结束；可断线重连 | 进入新版 |
| 旧局结算后返回大厅 | 自动载入新版，正常网络下约10秒内完成检查 | 进入新版 |
| 新版启动失败 | 当前版本继续运行 | 仍进入当前版本 |
| 第一次把旧服务换成热更入口 | 需要一次计划停服，必须等旧局结束后操作 | 安装完成后重新进入 |
| 重启容器、服务器断电、程序崩溃 | 对局会中断，目前没有完整对局存档恢复 | 服务恢复后重新开局 |

“热更”不会把新代码塞进玩家正在打的那一局。所以正在玩的玩家暂时看不到本次修改，这是预期行为。打完后点返回大厅即可；如网络异常没有自动切换，重新打开不带 `/_build/` 的游戏首页。

**日常热更只上传到新目录，再输入 `update`。不要覆盖旧目录、运行旧 `apply-update.sh`、重启 Docker 或执行 `docker compose up`。**

## 第一次安装：只做一次

文件夹里提供 `hot-server-v0.2.1-r01.tar.gz`，这是整合官方 v0.2.1 和定制多人规则的服务器首次安装包。以下命令在腾讯 OrcaTerm 的 **Shell终端** 输入，逐段执行。它不会自动停止旧游戏。

1. 用腾讯文件上传功能，把 `hot-server-v0.2.1-r01.tar.gz` 放到 `/home/ubuntu/`。不要放到旧游戏目录。

2. 解压并安装Linux运行依赖。这一步可在旧游戏正常运行时准备。

```bash
sudo mkdir -p /home/ubuntu/stronghold-hot
sudo tar -xzf /home/ubuntu/hot-server-v0.2.1-r01.tar.gz -C /home/ubuntu/stronghold-hot
sudo docker run --rm -v /home/ubuntu/stronghold-hot/releases/r01:/app -w /app node:22-bookworm-slim npm ci --omit=dev --ignore-scripts --no-audit --no-fund
```

依赖安装必须成功，出现下载错误先解决，不能继续切换。完整素材和前端库已经包含在包内。

3. 在不占用旧端口的情况下检查启动，测试服务只监听本机 `14518`，不用更改腾讯防火墙。

```bash
sudo docker run -d --name stronghold-hot-check -e HOST=0.0.0.0 -e PORT=14518 -v /home/ubuntu/stronghold-hot/releases/r01:/app:ro -w /app -p 127.0.0.1:14518:14518 node:22-bookworm-slim node server/hot/gateway.mjs /app
```

```bash
curl -fsS --retry 20 --retry-all-errors --retry-delay 2 http://127.0.0.1:14518/healthz
```

看到 `"ok":true` 才算启动检查通过。失败时查看 `sudo docker logs stronghold-hot-check`，不要停旧服务。

4. 通知玩家维护，等原来的对局结束。只有这次首次迁移需要停旧容器。下面按你之前截图中的旧容器名 `stronghold-game` 操作：

```bash
sudo docker stop stronghold-hot-check
sudo docker rm stronghold-hot-check
sudo docker stop stronghold-game
cd /home/ubuntu/stronghold-hot
sudo docker compose up -d
```

5. 检查新入口：

```bash
curl -fsS --retry 20 --retry-all-errors --retry-delay 2 http://127.0.0.1:14517/healthz
curl -fsS http://127.0.0.1:14517/__hot/status
```

健康检查应有 `"ok":true`，状态应有 `build` 和 `versions`。用原来的 `http://服务器公网IP:14517/` 进入游戏。腾讯已有允许TCP14517的规则即可，不需要加其他公网端口。旧容器、旧文件保留供首次安装失败时回退。

首次安装失败回退（仅适用于这一阶段、尚无新对局时）：

```bash
sudo docker stop stronghold-hot
sudo docker start stronghold-game
```

## 以后每次热更：上传、切换、检查

下面用下一次版本 `r02` 举例。每次使用新的编号：r03、r04……不可重复覆盖。这里的 r02 是操作示例，本次没有假装提供一个尚未制作的“下一版”。

1. 把下一次我给你的 `hot-release-r02.tar.gz` 上传到 `/home/ubuntu/`。包内应是 `releases/r02/`。

2. 解压并安装依赖，旧对局在这段时间继续运行：

```bash
sudo tar -xzf /home/ubuntu/hot-release-r02.tar.gz -C /home/ubuntu/stronghold-hot
sudo docker run --rm -v /home/ubuntu/stronghold-hot/releases/r02:/app -w /app node:22-bookworm-slim npm ci --omit=dev --ignore-scripts --no-audit --no-fund
```

安装成功后再继续。整个 `releases/r02` 都是独立新目录。

3. 连接热更服务的指令窗口：

```bash
sudo docker attach --sig-proxy=false stronghold-hot
```

这时进入了**游戏服务指令窗口**，不是Linux Shell。按一次回车，然后输入：

```text
update /releases/r02
```

看到“新版……已启用；旧版本对局继续运行”和“当前版本目录已记录”才表示切换成功。这里的 `/releases/r02` 是容器内部路径，不能写成 `/home/ubuntu/...`。

如果提示“更新未启用，当前版本继续运行”，旧版仍接待玩家，不必重启。先查新包路径、依赖和报错。

4. 在同一个指令窗口输入：

```text
versions
```

每行是一版：`current:true` 是新入口，`draining:true` 是只保留旧对局的版本，`matches` 是对局数，`connections` 是连接数。新旧版暂时同时运行是正常的。

退出这个指令窗口：**按住Ctrl先按P，再按Q，松开Ctrl。**这是Docker的分离组合键，服务继续运行。不要按Ctrl+C来退出；即使本流程关闭了信号转发，也不要用它作为正常退出方法。

5. 回到Linux Shell检查：

```bash
curl -fsS http://127.0.0.1:14517/__hot/status
cat /home/ubuntu/stronghold-hot/state/current
sudo docker stats --no-stream stronghold-hot
```

`build` 应是刚启用的版本，启动记录应是 `/releases/r02`。打开游戏首页检查新公告。正在打的旧玩家保留旧局；打完返回大厅再载入新版。

## 清理旧版本

等旧玩家打完、离开旧版页面后，重新 `docker attach --sig-proxy=false stronghold-hot`，输入 `versions`。

旧版本必须同时满足 `matches:0` 和 `connections:0`，才输入：

```text
retire 把这里换成versions显示的旧版本id
```

例如ID形如 `509e62675fed-1`，不是 r01 文件夹名。服务会再次核对，仍有对局或连接时拒绝清理。不会删除磁盘文件。最多并存三个版本；达到上限时等旧局结束、清理旧版本后再更新。

不要使用 `kill` 或重启容器强行清理。长期挂在结算页的玩家也可能让旧版暂时不能清理。

## 新版有问题，如何回退入口

回退也当作一次热更处理，保留当前进行中的新旧对局。先在Shell复制先前已验收的整版到新目录，例如：

```bash
sudo cp -a /home/ubuntu/stronghold-hot/releases/r01 /home/ubuntu/stronghold-hot/releases/r03-rollback
sudo docker attach --sig-proxy=false stronghold-hot
```

再在服务指令窗口输入：

```text
update /releases/r03-rollback
versions
```

按Ctrl+P、Ctrl+Q分离。新进来的玩家使用回退版；已经在问题版本里开始的对局仍继续原版本，不会强制终止。如果已经并存三个版本，仍要先等空闲版本满足清理条件。

## 公屏滚动公告

在热更服务指令窗口里输入（不是Shell）：

```text
announce 更新已完成，当前对局不受影响，本局结束后返回大厅即可进入新版
```

会发给所有保留版本。按Ctrl+P、Ctrl+Q退出指令窗口。

## 已验证与限制

本地测试已经覆盖：真实战斗中启用新版本、旧连接保持、旧玩家断线恢复身份、继续后续回合并自然结算、新入口切换、拒绝旧版再开新局、新版启动失败保持当前版，以及结算返回大厅的浏览器自动切换。

首次安装会终止旧容器中的剩余对局，所以必须安排维护并等对局结束。日常游戏代码热更不需要停入口。但更新入口本身、Node/Docker、重启系统都仍属于维护。启动记录仅记住当前目录，不保存对局。

新旧进程并存会增加CPU和内存使用。这次没有在腾讯上执行Docker安装，也没有验证200人并发；不能把本地热更通过当作线上负载保证。此流程不需要修改腾讯防火墙策略。
