# r18 同步与绘制优化 · 2026-10-09

已发布 `/releases/r18`，运行代号 `f1f917eba035-9`。默认入口已切换；r16、r17 工作进程及其在线对局保留，没有重启网关或退役旧版本。

## 行为

- 新客户端在 hello 中声明 `stateDelta: true`；服务端确认后，按连接分别维护 `m.public`、`m.private` 的基线。首次发送和每32次更新使用完整状态；增量只有在明显更小时才使用。发送成功入队才推进基线。
- 增量包含基线序号和新序号。浏览器在应用分发前恢复原消息，保护基线不受界面对象修改影响；缺失基线、序号异常或非法路径时重连并取得完整状态。旧客户端继续接收原完整消息，旧服务器忽略新的可选 hello 字段。
- 广播按相同基线复用准备结果，缓存采用弱引用及每消息32项上限。个人私有状态仍只发给本人；战斗输入、结果和快照不做增量编码。
- WebSocket 大消息协商 `permessage-deflate`：门槛2048字节、level 1、并发2、双向关闭 context takeover。小控制消息绕过压缩；原64KB入站上限及拥塞保护保留。`SP_STATE_DELTA=off`、`SP_WS_COMPRESSION=off` 可在启动新进程时用于关闭对应功能。
- 设置新增60／30 FPS，默认60，保存后可随时切换。只限制 Pixi 绘制 ticker；客户端战斗 runner 和计算步长不变。自适应降负载按目标帧率判断，主动30帧不会被误判为持续卡顿。手机保持横屏，新增按钮触摸区域至少48×44px，并支持方向键切换。
- 更新公告包含上述变化，保留克莱门莎的红色强调公告。

## 回放压力测试

使用真实8人 Match 的365条公共／个人状态样本，64个本地回环连接，每连接每秒20条状态，5秒共6400条。个人样本按各连接分别处理。三种模式独立进程运行，每条消息解码后与完整状态逐项比较。

| 模式 | WebSocket 写入字节 | 进程 CPU 时间 | 事件循环最大延迟 | 峰值 RSS |
| --- | ---: | ---: | ---: | ---: |
| 原完整状态 | 33,585,650 | 406 ms | 19.97 ms | 193 MB |
| 增量 | 5,881,418 | 1,343 ms | 27.75 ms | 207 MB |
| 增量＋大消息压缩 | 4,071,626 | 1,390 ms | 24.07 ms | 230 MB |

最后一项比完整状态减少约87.9%的写入字节，无消息缺失或持续队列积压。CPU增加，不能宣称降低了总计算成本。这里的 CPU 同时包含服务器编码、模拟测试客户端及解码／断言；字节统计包含 WebSocket 帧，不是全站 TCP 流量或生产环境节省比例。
